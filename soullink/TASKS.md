# Soul Link 작업 보드

최종 갱신: 2026-10-22

이 문서는 현재 상태만 다루는 실행 목록이다. 프로젝트 구조와 인수인계 정보는
`ABOUT.md`, 세부 설계와 과거 검증 기록은 `docs/`를 참고한다.

## 현재 상태

- 공개 게임: `https://recoba00.github.io/Codex-Games/soullink/`
- 온라인 API: `https://soullink-match.recoba00.workers.dev`
- 저장소: `https://github.com/recoba00/Codex-Games`, `main`, 게임 폴더 `soullink/`
- 엔진: Godot 4.7.2, GDScript, GL Compatibility, 모바일 세로 390x844 기준
- 출시 순서: Apps in Toss 우선, 이후 Steam과 Google Play
- 비용 원칙: Cloudflare/Supabase 무료 범위만 사용. 결제수단, 유료 플랜, 자동 과금 금지
- 최근 기능 수정: 초대 코드 모바일 키보드 활성화 및 키보드 포커스 자동 확대 방지
- 현재 화면 흐름: 인트로 → 로비 → AI/초대방 준비 → 대전 → 결과 → 로비.
  상점·랭킹·공개 매칭은 비활성 자리만 있으며 세부 동선은 `docs/GAME_FLOW.md` 참고.
- 최근 검증: Node 40개, Godot 코어 14,681검사, 로컬 어드민 51검사 통과.
  GitHub Web export/Pages/Worker 자동 배포 구성. 배포 상태는 해당 커밋의 Actions에서 확인.

## P0 - 다음 작업

- [ ] P0-DEVICE-001: 실제 iPhone/Android에서 온라인 초대 입력을 검증한다.
  키보드 열기/닫기, 화면 배율 유지, 코드 8자리 입력, 참가 버튼, 세로 안전영역,
  브라우저와 홈 화면 추가 실행을 각각 확인한다. 문제가 있으면 기기/OS/브라우저와
  재현 영상을 기록한다.

- [ ] P0-ONLINE-RESULT-001: 서버 권위 경기 결과를 Supabase에 영구 저장한다.
  Worker만 `match_results`를 쓰고 클라이언트는 자기 경기만 읽게 한다. 중복 저장 방지,
  재접속/기권/시간초과/비정상 종료, 익명 계정 수명과 데이터 보존 정책을 테스트한다.
  `SUPABASE_SERVICE_ROLE_KEY`는 Cloudflare secret으로만 넣고 Git/클라이언트/로그에
  노출하지 않는다. 실제 secret 등록은 별도 승인 후 진행한다.

- [ ] P0-RANK-001: 테스트용 랭킹과 티어의 최소 규칙을 확정한다.
  권장 시작안은 시즌 Elo/MMR + 배치 경기 + 브론즈/실버/골드/플래티넘/다이아 티어다.
  익명 계정 악용, 동일 상대 반복, 중도 이탈, 시즌 초기화, 동률 정렬을 먼저 정의하고
  결과 저장이 안정화된 뒤 UI를 연결한다. 현재 공개 게임에는 랭킹이 없다.

- [ ] P0-TOSS-001: 최신 Web 빌드로 `.ait`를 다시 만들고 Toss 콘솔/QR 실기기 검증을 한다.
  최초 로딩 시간, 약 39.5MB WASM 메모리, SafeArea, 뒤로가기/닫기, BGM, 터치 드래그,
  온라인 WebSocket, 모바일 키보드와 확대 방지를 확인한다. Devtools 모의 검증만으로
  완료 처리하지 않는다.

- [ ] P0-CONTENT-001: 배포 없이 캐릭터/스킨을 운영할 HTTPS 콘텐츠 경로를 확정한다.
  현재 로컬 어드민과 라이브 카탈로그는 동작하지만 공개 운영 관리자/게시 파이프라인은
  없다. Supabase Storage/DB를 우선 후보로 검토하고, 공개 읽기와 관리자 쓰기를 분리한다.
  어드민은 게임 빌드에 넣거나 공개 경로로 노출하지 않는다.

## P1 - 품질과 운영 기반

- [ ] P1-FLOW-001: 공개 매칭 큐가 준비되면 매칭 성립 후 비공개 동시 캐릭터 픽,
  스펠 확정, 공개 연출을 서버 계약과 함께 구현한다. 현재 초대방은 방 생성/참가 시
  캐릭터를 확정하므로 화면만 앞세워 가짜 픽을 만들지 않는다.

- [ ] P1-ASSET-001: 배포 전 이미지 경량화와 용량 예산을 자동화한다.
  첫 단계로 Web 출력 크기/운영 파일 혼입 CI와 어드민 등록 전후 크기 표시는 완료했다.
  VFX 무손실 WebP는 실제 PCK 절감이 없어 원본 PNG를 유지했다.
  현재 깨끗한 Web 파일 기준 약 57.38MiB, WASM 37.68MiB, PCK 13.27MiB다.
  남은 일은 일반 원화/배경의 품질 비교 자동화와 표시 크기별 배포본 선택이다.
  원본은 보존하고 배포본만 실제 표시 크기로 축소한다. 일반 원화/배경은 육안 차이가
  없는 WebP, 알파가 중요한 UI/VFX는 lossless WebP 또는 최적화 PNG를 사용한다.
  해상도·알파·색상·파일 크기 전후를 검사하고, 캐릭터 원화는 자동 과압축하지 않는다.
  변경된 에셋별 바이트와 전체 Web/PCK 크기를 CI 산출물에 남긴다.

- [ ] P1-ARCH-001: 실기기 로딩/프레임/메모리를 먼저 측정하고 실제 병목만 최적화한다.
  `scripts/ui/main.gd`는 화면 조립과 온라인/전투 조율이 큰 파일이다. 관련 함수 진입점을
  `docs/AI_WORKFLOW.md`에 지도화했다. 무작정 분리하지 말고 독립된 책임이 확인될 때
  테스트와 함께 작은 컨트롤러로 추출한다. UI/전투 동작은 그대로 유지한다.

- [ ] P1-MOBILE-001: 360x800, 390x844, 430x932와 가로 회전에서 UI 실기기 회귀를 한다.
  퍼즐 터치 영역, 키보드, 결과 화면, 노치, 주소창 축소/확장, visual viewport 변화를 본다.

- [ ] P1-COMBAT-001: 캐릭터별 10~20판 체감 테스트와 수치 조정을 진행한다.
  기본 타격, 빨강 추가 피해, MP 보유/사용, 회복 선택, AI 의도, 패시브와 상성 5%가
  단순하면서도 가위바위보처럼 느껴지지 않는지 기록한다.

- [ ] P1-COMBAT-002: 온라인 스펠 규칙을 서버에 구현한다.
  현재 온라인에서는 서버 규칙이 없어 별도 1회 스펠을 명시적으로 비활성화한다.
  비용/횟수/대상/재연결 영수증을 서버 권위로 만든 뒤 클라이언트 버튼을 연다.

- [ ] P1-MATCH-001: 공개 매칭 전 입장 제한과 운영 계측을 보강한다.
  초대방은 동작한다. 공개 큐, 동시 접속 제한, 지역/지연, 재매칭, 신고/차단은 미구현이다.
  무료 한도 근접 시 유료 전환하지 말고 새 방 생성을 실패시키도록 유지한다.

- [ ] P1-ADMIN-001: 캐릭터/스킨 게시자의 인증, 감사 로그, 롤백과 백업을 구현한다.
  현재 어드민은 PC loopback 전용 단일 운영 도구다. 인터넷에 그대로 노출하지 않는다.

- [ ] P1-PWA-001: 설치형 Web 범위를 결정한다.
  manifest와 홈 아이콘은 있으나 정식 오프라인 PWA/service worker는 제공하지 않는다.
  새 버전 캐시, 대용량 WASM/PCK 갱신, 강제 새로고침 정책을 정한 뒤 도입한다.

- Supabase 결과 쓰기용 service-role Worker secret 등록.
- Toss 개발자 콘솔 업로드와 실제 기기 QR 테스트.
- 운영용 캐릭터/스킨 콘텐츠 호스트 및 관리자 인증 방식 결정.
- 유료 서비스 도입은 제품명, 예상 비용과 한도를 명시한 사용자 승인이 있기 전 금지.

## 완료 기준

각 항목은 코드 작성만으로 완료하지 않는다. 관련 자동 테스트, 실제 대상 환경 확인,
브라우저 경고/오류 확인, 문서 갱신, `main` 푸시, GitHub Actions 성공, 공개 URL smoke test를
마쳐야 `[x]`로 바꾼다. 모바일/토스 항목은 실제 기기 증거가 없으면 완료로 표시하지 않는다.
